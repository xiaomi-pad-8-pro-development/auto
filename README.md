# Kernel build script for the Xiaomi Pad 8 Pro (piano)

Builds the [alxp kernel](https://github.com/xiaomi-pad-8-pro-development/android_kernel_xiaomi_piano)
and turns it into the prebuilts in
[android_device_xiaomi_piano-kernel](https://github.com/xiaomi-pad-8-pro-development/android_device_xiaomi_piano-kernel):

| Output | What it is |
| --- | --- |
| `Image` | The kernel |
| `dtb/` | Base devicetrees with the Qualcomm techpack overlays merged in |
| `dtbo.img` | The piano board overlay, merged the same way |
| `modules/vendor_boot/dlkm.cpio` | First stage and recovery modules, as a vendor ramdisk fragment |
| `modules/vendor_dlkm/`, `modules/system_dlkm/` | The other modules with their `modules.load` |
| `kernel-headers/` | UAPI headers, including the techpack ones |

Modules are stripped and signed with the key the kernel was built with, and
each partition gets only the modules on its list in `build_config/piano`.
Repeated entries are removed while retaining the original load order, and
the build stops if a required module was not compiled. `module_preflight.py`
checks the load lists before the build and rewrites the unqualified
`softdep` lines depmod writes (`softdep cifs ecb`) into the `pre:` form
Android's module loader accepts; `python3 -m unittest discover -s tests`
runs its checks.

## Usage

```
ROM_DIR=~/android/<rom> ./build.sh
```

Set `KERNEL_DIR`, `OUT_DIR`, `LLVM_DIR` or `PREBUILT_KERNEL_DIR` to override
their defaults (see the top of `build.sh`). `COMMIT=1` commits the result in
the prebuilt repository.

The kernel builds without root by default, as official ROM builds need.
`KSU=1` builds the root variant with KernelSU-Next and SUSFS
(`piano_ksu.config`). The prebuilt repository keeps each on its own branch:
`seventeen` without root, `seventeen-ksu` with it. Checkout the corresponding
branch in `PREBUILT_KERNEL_DIR` before building: the script refuses a mismatch
in a Git checkout so one variant cannot overwrite the other's release.

Needs the kernel source, clang `r510928` (the version stock was built with),
and a ROM checkout for `mkdtboimg.py` and `kernel-build-tools`.
`fdtoverlaymerge` is built from Qualcomm's dtc on the first run.

## Reproducibility

`build.sh` defaults `SOURCE_DATE_EPOCH` to the kernel commit time, sets a fixed
kernel build timestamp and build number, and normalizes timestamps and metadata
in the generated vendor ramdisk. The build user and host are fixed as well.
Set `SOURCE_DATE_EPOCH`, `KBUILD_BUILD_TIMESTAMP`, or `KBUILD_BUILD_VERSION`
explicitly when a release needs other values. Use the same source revision,
toolchain, build paths, and signing key when comparing output hashes.

The kernel's autogenerated module-signing key is saved in `OUT_DIR` and reused
for incremental builds. A fresh `OUT_DIR` generates a different key, so output
from two clean builds is not bit-for-bit identical, and a new kernel rejects
the signatures of modules already on the device. Set `MODULE_SIG_KEY` to a PEM
file holding the private key and its certificate to sign every build with the
same key. Keep that file private and out of every repository.
